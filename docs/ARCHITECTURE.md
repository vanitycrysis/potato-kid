# Architecture

How the code is laid out and how the parts talk. This is the current state; the original plan is `docs/archive/ENGINEERING_PLAN.md`.

## Stack

TypeScript (strict), PixiJS v8 for the map, a DOM overlay for the UI, Vite to build, Capacitor for Android, Vitest for unit tests, Playwright for end-to-end tests and for rasterising art (D-014).

## The shape of it

```
            commands                      events
  UI (DOM) ─────────▶  Game (sim, 10 Hz) ─────────▶  MapScene (Pixi, every frame)
     ▲                     │      ▲                        │
     │ reads state         │      │ reconcile(now)         │ draws kids from the rig,
     └─────────────────────┘      │                        │ interpolated between steps
                         SaveManager / Lifecycle
```

- **The sim is pure.** `Game.step(commands, dt)` advances the world by a fixed 0.1 s and returns events. It knows nothing of Pixi or the DOM, uses seeded random streams, and is the same code the balance simulator runs.
- **The scene draws.** `MapScene.frame(dt)` runs every animation frame: it steps the sim as often as time requires, interpolates kid positions between steps, and draws. It also owns input on the map (drag, tap, pinch, pan).
- **The UI is DOM.** It reads the game's state each frame and sends commands. UI touches never start a map drag (D-022).
- **Time away** is one call: `Game.reconcile(now)` credits everything since `accountedUntil` in closed form, with no fusions (D-018, D-028, D-080).

## Folders

| Folder | What is in it |
|---|---|
| `src/sim/` | The simulation: `game.ts` (the `Game` class: commands, the step, spawning, fusion, planting, farming, feeding, purchases, offline catch-up), `world.ts` (kids, activities, wandering), `space.ts` (the no-overlap rules), `visits.ts` (decorations), `offlineWander.ts`, `names.ts`, `rng.ts`, and the balance simulator (`balance.ts`, `balance-cli.ts`) |
| `src/content/` | Game data and its rules: `kids.json`, `recipes.json`, `balance.json`, `validate.ts` (the content contract, run at boot and in tests), `artData.ts` (loads the art sidecars from `assets/data/`), `artRules.ts` (turns art data into what the sim needs: boxes, rest timings, obstacles, the motion overlay) |
| `src/render/` | The map: `scene.ts` (`MapScene`: camera, input, the frame loop, fusion ghosts), `rigView.ts` (one kid drawn from the rig), `presentation.ts` (which clip a kid shows), `art.ts` (texture loading by type), and views for plots, fields, decorations, rares and the map itself |
| `src/ui/` | The DOM overlay: `hud.ts` (the frame, the HUD, wiring), `sheet.ts` (the modal shell), one file per sheet or widget (`buildings`, `gardenPlots`, `fields`, `dex`, `kidCard`, `newKidPopup`, `lessons*`, `tutorial`, `settings`, `offline`, …), `portrait.ts` and `animatedPortrait.ts` (kids drawn in the DOM) |
| `src/save/` | Saving: `manager.ts` (two alternating slots, protected slots on failure), `record.ts` (the record format, checksum, state validation; `SAVE_SCHEMA`), `migrations.ts`, `settings.ts` (player settings, apart from the save), `storage.ts` |
| `src/platform/` | `lifecycle.ts` (one coordinator for browser and native pause and resume), `back.ts` (Android Back) |
| `src/audio/` | `player.ts` (Web Audio runtime), `cues.ts` (which sound a step gets) |
| `src/main.ts` | Boot: loads the save, the art and the fonts, builds the scene and the HUD, starts the loop, and exposes the test hooks |
| `art/` | Art sources (`art/src/**/*.svg`), authored data (`art/data/*.json`), motion scripts (`art/motion/*.mjs`), review material. See `docs/ART.md` |
| `assets/` | What the app loads: exported PNGs and SVGs, the copied sidecars (`assets/data/`), audio, the font. Generated by `npm run art:export`; committed |
| `scripts/` | `export-art.mjs`, `check-kids.mjs`, `build-motion.mjs`, `balance.mjs`, audio build scripts, `android-res.py` |
| `tests/e2e/` | End-to-end specs, one file per area. See `docs/TESTING.md` |
| `tests/preview/` | Review captures through the engine. Not part of CI |
| `android/` | The Capacitor Android project |

## Things worth knowing before changing code

- **Kids are drawn from data.** `art/data/kid_rig_v2.json` (bodies, faces, costumes, Codex's clips) with `kid_activity_v1.json` (farming and decoration frames) and `kid_motion_v1.json` (Claude's motion) laid over it. `artData.ts` exports `kidRig` (for DOM portraits) and `mapRig` (for the map and the sim, with motion and the grown boxes). Wild kids come from `kid_wild_v1.json`.
- **A kid's box comes from the art**, never from the save: `Game.restore` recomputes every box on load and moves a kid that no longer fits (`src/sim/game.ts`).
- **Activities** (`src/sim/world.ts`): `walk`, `pause`, `look`, `wave`, `habit`, `sit`, `sleep`, `visit`. The sim picks them; `ClipPicker` maps each to a clip. Adding one means: the type, `record.ts` validation, a save schema bump with a migration, `ClipPicker`, and the rest weights in `artRules.ambientFrom`.
- **Saves:** bump `SAVE_SCHEMA` and add a migration for any change to what is saved, even one an old save needs no change for (an older build must refuse a newer save). Unreadable storage is never treated as empty (D-029).
- **Random streams:** `rng` (game outcomes), `spawnRng` (what the Garden makes), `cosmetic` (looks, rests). Keep cosmetic choices on the cosmetic stream so they never change outcomes.
- **Test hooks:** with `?debug=1` the app exposes `window.__PK__` (add a kid, pose it, give Materials, skip time). They are declared at the top of `src/main.ts`. `?calm=1` stops wandering and starting kids. The hooks ship in the production bundle; removing them from release builds is open work.
- **Texture budget:** decoded textures stay under 32 MiB (D-034). Costume textures load when a type first appears and are released after it leaves (`TextureStore`); `src/render/budget.test.ts` checks the worst case.
- **The two largest files** are `src/sim/game.ts` and `src/render/scene.ts` (about 1,850 lines each). Splitting them is approved (D-101) and not done: `visits.ts` is the model for moving planting, farming and feeding out of `game.ts`; input handling can leave `scene.ts` for a module of its own.
