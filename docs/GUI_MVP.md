## 2. Viewport, layers and modal behaviour

Let W/H be visualViewport CSS dimensions. Portrait (H>520): ST=max(24, top safe inset), SB=max(24, bottom safe inset). Compact (H≤520): ST=max(8, top safe inset), SB=max(8, bottom safe inset). Left/right margins ML/MR=max(8, corresponding safe inset); no notch-covered targets. U=H−ST−SB. Reference guides are 24/24 for both phones and 8/8 for 640×360. Re-measure on rotation, viewport resize and safe-inset changes.

Z-order: world 0; HUD/tray/Dex 10; world feedback 20; modal scrim 40; sheet 50; sheet-local feedback 60; global save banner 80; read-only input shield 5 (below browsing UI but above world). Scrim is ink at **0.24 opacity**, no blur. Exactly one sheet at a time. Modal opening fades scrim 0→0.24 and translates sheet 12 px upward to rest over **160 ms ease-out**; close reverses over **120 ms ease-in**. Reduced motion: no translation or transition. No spring, bounce, drag-to-dismiss or sheet handle.

Opening: finish/cancel any held-kid gesture using the engine's existing cancelDrag landing rule **before** displaying a scrim. If a world drag is still resolving, defer modal opening until its cancellation completes. UI pointer/touch events never reach Pixi; stop propagation/capture appropriately. While a modal is open, world pickup/pan/edge-scroll input is paused, **not simulation or Materials income**. Disable background DOM focus via inert; trap focus in sheet, focus heading (or close button if necessary), return focus to launcher on close. Escape, Android back, outside tap and the 44 px X close ordinary sheets; clicking inside never closes. Offline summary uses the same close paths. A banner's dismissal never dismisses a sheet.

Sheet geometry: SW=min(600,W−ML−MR), centred horizontally; bottom H−SB. Available height UA=U minus the height+8 of an active global banner. Normal maximum SH=min(requested height,floor(0.8×UA)); compact SH=min(requested height,UA−16). Requested heights: Garden/Capacity **440**, Bias/picker/Compendium/Dex **624**, Offline/Settings **480**. This gives Garden at [8,380,374,440], large sheet at [8,196,374,624], summary at [8,340,374,480] on 390×844. At 390×693 Garden y229/h440, large sheet y153/h516, summary y189/h480. On 640×360 every sheet is [20,24,600,328]. With save banners the sheet shrinks so its top is at least ST+bannerHeight+16; banner stays visible.

All sheets: 8 px border; interior horizontal padding **8 after border** (content x=sheetLeft+16, C=SW−32). Header **80** high measured from outer top, including border; icon at [16,24,28,28], title begins x52/y20, close [SW−60,16,44,44]; subtitle/body at x16/y58. Compact header **64**: icon [16,8,24,24], title x48/top8 (SVG baseline30), close [SW−60,8,44,44], subtitle x16/top40 (baseline56). Level/progress/subtitle always remains visible. Long titles wrap and grow header instead of truncating. Bottom footer **80** including bottom border; padding 8 after border, one 48 px action and 8 px free space. Dex/Compendium have **no persistent purchase footer**; content continues to bottom interior at SH−16. Header, tabs and purchase footer stay fixed; only body scrolls vertically. Body uses 8 px gaps, 16 px bottom padding, overscroll containment; native scrollbar styled 6 px secondary-ink thumb on sage track (no arrows). Scroll shadows are absent. Content may cut off at the viewport boundary as a scrolling cue; never clip a focused item/required action (scroll it into view). At text zoom, these are minimum sizes and body/footer/header grow; sheet maximum remains safe and controls can scroll as a last resort.

World feedback and banners count as occlusion for MapScene.setInsets; measure their actual rectangles along with HUD/tray/Dex. Preserve a ≥44 px unobscured play band on tiny screens by queueing transient feedback until banners/sheets free room. While dragging, do not mount a new toast/banner/modal over the held-kid corridor: queue ordinary feedback; cancel drag before urgent save/read-only transitions. No rewards vanish merely because a kid is held.

### Number display (algorithm implementation is engineering)

Nonnegative currency balances: floor first for whole Materials, integer Potatokens. <1,000 uses exact digits. From 1,000 use k/M/B/T at factors 10³/10⁶/10⁹/10¹², **truncate to one decimal**, omit trailing .0, never round upward. Examples: 999.99→999; 1,299.99→1.2k; 999,999→999.9k; 1,000,000→1M. ≥10¹⁵ uses one-decimal truncated scientific display, e.g. `1.2e15`. Show full floored value in accessible label/title; no clickable currency popover. Counter slot never abbreviates a cost. **Every purchase price is exact**, grouped with commas; wrap to two lines/increase the button when necessary. Affordability uses raw balances, not displayed numbers. Time comparisons use engine seconds; countdown uses ceil then mm:ss. Building interval uses one decimal second, nearest0.1; offline time rounds down whole seconds and displays `2 h 14 m`, `4 m 02 s`, or `12 s` as applicable. Reward totals use whole Materials floor and exact Potatokens; offline Materials can show abbreviated main value with exact whole value in parentheses underneath when abbreviated. Engineering owns locale handling without changing the hierarchy.
